# 魅族抬起手势适配

`sensors.m2381.so` 通过 Multi-HAL 2.1 加载未修改的 `sensors.ssc.so`，保留
原有私有传感器，并增加标准 `PICK_UP_GESTURE` 唤醒型一次性接口。

原厂 `RaiseFlipperController` 以动作码 6，或者前序动作不是 6/7 时的动作码 2
触发唤醒；动作码不是角度或完成百分比。适配层采用相同的抬起判定，不模拟
加速度算法。屏幕唤醒、防口袋误触及设置开关交由 SystemUI 的原有手势链路处理。

原厂 raise 接口是 on-change；标准接口是 one-shot。适配层序列化底层启停，
收到有效动作后先解除标准接口的订阅，再转发一次标准事件。私有接口有其他
订阅者时继续保持原厂传感器开启，取消标准接口不会打断私有订阅。排队事件带
监听代次及原始时间戳，防止取消或重新监听后重放旧事件。

事件转发使用 Multi-HAL 自身的 ScopedWakelock，原始唤醒锁一直保留到新批次
接管；没有常驻加速度采样、轮询或长期唤醒锁。

行为回归测试：`m m2381-pickup-test`。测试二进制不打包到产品中，测试覆盖：

- 标准 sensor 元数据和原厂私有传感器保留。
- 放置动作过滤、动作码前序状态和其他传感器事件转发。
- 一次性触发、再次监听、取消及旧时间戳拒绝。
- 私有接口与标准接口同时启用时的底层订阅归属。
- 禁止一次性接口 flush、禁止事件注入和直接报告。
- 原始事件及转换后批次的唤醒锁所有权。

这些模拟边界测试不能替代真机 SystemUI 的抬起亮屏、设置开关、遮挡及重启检查。
